🗺️ Code Lifecycle Tour: Adding a Study Topic

Follow one core user action through its 3 primary code locations:

🔍 Code Route: 3 Key Stops

1

The Entry Point: Controlled Form & Validation

src/components/TopicForm.jsx

When the user clicks "Generate Priority & Add to Queue", handleSubmit() executes validate(). It checks for non-empty strings, trims leading/trailing whitespace, and calculates calculateDaysRemaining(examDate). If the date is before today, it blocks submission and displays an inline red error alert without wiping the student's typed text.

2

The Signature Engine: Pure Calculation & Explanations

src/utils/priorityEngine.js

calculatePriority(examDate, confidence) contains zero DOM or React code. It computes local midnight day difference and returns a clean object with numerical score (10–95), tier (HIGH/MEDIUM/LOW/PAST DUE), CSS badgeClass, and plain-English reasoning text. Because this function is pure, it was verified with 100% automated test coverage in tests/verify_all.mjs.

3

State Coordination & Browser Storage

src/App.jsx

App.jsx coordinates state for topics, editingTopic, and topicToDelete. An initial lazy state initializer parses localStorage.getItem('examsprint_topics') inside a safe try...catch block, and a reactive useEffect synchronizes every topic addition, edit, completion, or deletion directly to browser storage.

💡 A Reusable Software Engineering Practice

Separating Core Domain Logic from UI Rendering:

Notice how the Priority Scoring algorithm lives entirely inside priorityEngine.js without any JSX, React state, or browser DOM dependencies.

By keeping the math pure, we were able to run an automated 40-test verification suite (node tests/verify_all.mjs) that verified all edge cases, date arithmetic, and point weights in milliseconds without needing to render a single HTML element. When you build future applications with AI agents, always isolate your business rules into pure JavaScript helper files before connecting them to UI components.
